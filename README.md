# Token Forge 设计令牌工作台

基于 SolidJS、TypeScript、Vite、Kobalte、Tailwind CSS、Solid Router 和 Style Dictionary 的本地设计令牌工作台。

## 运行

```bash
corepack pnpm install
corepack pnpm dev
```

生产构建：

```bash
corepack pnpm build
corepack pnpm tokens:build
```

协作修订测试（纯函数合并引擎 + 双窗口端到端，101 个断言）：

```bash
corepack pnpm test:collab
```

## 已实现功能

- 管理颜色、字号、间距、圆角、阴影和动效时长令牌。
- 多套主题切换、复制和本地持久化。
- 编辑令牌后组件预览实时刷新。
- 自动计算正文与关键颜色组合的 WCAG 对比度等级。
- 保存修改快照并比较两次修改之间的差异。
- 导入 JSON，导出 Style Dictionary JSON、CSS Variables 和 Sass Variables。
- `tokens:build` 使用 Style Dictionary 输出 CSS、SCSS 和扁平 JSON。

## 可续作的协作修订模型

两个窗口可以同时打开同一主题：一个窗口断网编辑，另一个继续改动，回来后不再整份覆盖。

- **改动先记账**：每次编辑都落为待处理操作，记录所属窗口（clientId）、令牌编号（tokenId）和当时的确认修订号（baseRevision）；同一窗口对同一令牌的连续编辑折叠。操作按窗口独立持久化（`token-forge-outbox-v1:<clientId>`），窗口重开认领身份后待处理改动还在。
- **逐令牌三方合并**：网络恢复后以各操作的基线修订为祖先、当前确认版本为目标，按令牌、按字段合并。互不相干的改动自动并入；同一字段被改成不同值、改名分歧、并行新增不一致，都会并排保留在「待处理改动与冲突」面板。
- **移除/改名不悄悄盖掉**：一方移除、另一方编辑（含改名）时挂出 remove-edit 冲突，令牌在确认版本中保持不动，可裁决移除、保留合并编辑、选某一方方案或维持确认版。
- **确认版本优先**：未裁决冲突期间，主题仍指向上一份确认修订；预览、版本差异、导出全部读确认版本，编辑器只展示本窗口「确认版 + 本地待处理改动」的草稿。
- **裁决即新快照依据**：冲突裁决提交后追加新的确认修订并自动生成「协作裁决提交」快照；旧修订链与旧快照全部保留，快照带修订号。
- **检查点与恢复**：每轮合并写入新修订前先落检查点（确认状态 + 各窗口 outbox）。合并失败不会写出半成品，确认版本不变；持检查点的窗口点「从检查点恢复」即可还原全部待处理改动并安全续作。状态栏提供「演练合并失败」入口。
- **在线状态按窗口独立**：可只断其中一个窗口的网；仍离线窗口的待处理操作不会被在线窗口提前消化。
- **数据升级**：旧版 `token-forge-workspace-v1` 数据首次打开时自动迁移为 v2：原主题与旧快照继续可用，旧快照登记在第 0 修订，之后的编辑在修订链上继续增长。

模拟两个窗口：在浏览器里开两个标签页即可（localStorage + storage 事件跨页同步）；状态栏会显示各窗口身份与在线情况。
